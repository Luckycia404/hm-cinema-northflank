/wefeed-mobile-bff/subject-api/get-ext-captions
/wefeed-mobile-bff/subject-api/get-captions

General playback sequence:

1. Client identifies a subject/movie/episode.
2. Client requests subject metadata and available resources.
3. Client supplies episode/season/resource information to playback resolver.
4. Server resolves the available playback resources.
5. Response may contain stream information, quality/format metadata, subtitle information, and temporary media URLs.
6. Native player/CDN handles playback.

Temporary playback URLs may be signed/time-limited and may depend on session, token, region, request metadata, or CDN rules.

23. IMPORTANT SECURITY OBSERVATIONS
=====================================================

The application contains multiple layers rather than a single API key:

- account authentication
- access/refresh tokens
- authorization headers
- client/device metadata
- gateway interception
- request signing
- CDN controls
- subscription/rights checks
- regional infrastructure

Therefore, simply discovering an endpoint does not guarantee direct browser access.

A browser may receive:
- a redirect
- a JSON response
- a temporary signed URL
- a CDN authorization error
- an authentication error
- a region/device restriction

28. FINAL SUMMARY
=====================================================

The application is a multi-service client, not a single movie API.

The architecture contains:

CONTENT
  movies / series / shorts / metadata / recommendations

PLAYBACK
  resources / play-info / captions / CDN

ACCOUNT
  login / registration / SMS / profile / tokens

SOCIAL
  comments / posts / groups / community

SPORTS
  live matches / upcoming matches / H5 sports integration

GAMES
  game center / H5 games / score reporting

MEMBERSHIP
  VIP / rights checks

INFRASTRUCTURE
  gateway / signatures / regional hosts / CDN / H5 / dynamic configuration

The most important technical chain is:

CLIENT
  -> gateway/client metadata
  -> authenticated or public BFF endpoint
  -> subject/resource resolver
  -> temporary media resource
  -> CDN
  -> player

For legitimate testing, the safest workflow is to use an account/content you are authorized to access and capture your own app session/request flow, rather than attempting to bypass authentication, subscription, geographic restrictions, or CDN authorization.
